# Reconstructing Algorithm 3 and Note 9

This is the backtracking route from article §6, not the separate
[code-group intersection](ccz-stabilizers.md). Its purpose is to make the
historical construction understandable and reproducible: start with no known
self-equivalences, find generators recursively, and turn the generators into
cheap restrictions on the search for the next one. A computer algebra system
calculates orders of the groups generated by the returned permutations.

The readable implementation is
[historical_stabilizer.py](../lib/historical_stabilizer.py); the optional
[Cython implementation](../cython/ea_stabilizer.pyx) preserves shared value
buffers, copied masks, and recursive alpha/beta/gamma refinement.
[historical_stabilizers.sage](../sage/historical_stabilizers.sage) drives the
experiments and saves full transformation witnesses and each subgroup step.

From `artifacts/`, start with the small readable experiment:

```sh
sage -python sage/historical_stabilizers.sage --reference --max-dimension 4 \
  --output build/historical-stabilizers-reference4.json
# All nine supplied n=4,5 representatives, with Cython acceleration:
make historical-stabilizers
# Replay saved certificates and group arithmetic without repeating the search:
make verify-historical-stabilizers
```

To run only the Note 9 generator search, without waiting for the other n=5
functions, the following short Sage/Python example uses the same implementation:

```sh
sage -python - <<'PY'
import json, sys
sys.path.insert(0, 'lib')
from compiled import load_kernel
from historical_stabilizer import canonical_generators
with open('data/dimension-five.json') as stream:
    table = json.load(stream)['representatives'][0]['table']
kernel, _ = load_kernel('ea_stabilizer')
group, generators, steps = canonical_generators(table, kernel.search)
for step in steps:
    if not step['exhausted']:
        print('alpha =', step['alpha'])
print('EA stabilizer order:', group.order())
print('Final search exhausted:', steps[-1]['exhausted'])
PY
```

This example discovers the generators from scratch; it does not seed the
search with the published permutations. The full runner additionally compares
the discovered sequence with them and retains beta/gamma witnesses.

## The concrete Note 9 construction

The three printed permutations are transcribed as cycles in the Sage runner.
No unpublished operators are needed to reconstruct this example. Compute
orbits by repeatedly applying just the selected permutations:

| Position being minimized | Generators retained | Earlier positions fixed | Orbit |
| ---: | --- | --- | --- |
| 0 | h1, h2, h3 | none | all 32 positions |
| 1 | h1, h2 | 0 | all 31 nonzero positions |
| 2 | h1 | 0, 1 | {2,17,25,22,28} |

Because alpha is a permutation, the least value in the first orbit is 0.
After fixing alpha(0)=0, the least remaining value is 1. The five-position
orbit then supplies comparisons with alpha(2). These are exactly the printed
rules:

```text
alpha(0) = 0,
alpha(1) = 1,
alpha(2) <= alpha(j), j in {17,22,25,28}, whenever both values are known.
```

The [literal filter](../lib/historical_stabilizer.py) is named
`printed_note9_filter`. The general `generator_orbits` helper implements the
same construction: for position x, retain the already known generators fixing
every y<x, and follow their cycles from x. It does not call a full stabilizer
routine or manufacture additional generators. For the printed example there
are no further nontrivial orbits after these three stages.

Marcus confirmed this practical interpretation on 20 September 2026: the
interlocking cycles and their fixed positions were the facts used to obtain
the restrictions, with computation on a Pentium 4 as the immediate objective.
The general proofs and exhaustive checks below are explanatory verification
added in this reconstruction. They are not a claim that a more elaborate
group-theoretic implementation existed in the original experiment.

## Which side acts on alpha?

Write composition explicitly as

```text
T(x) = beta(S(alpha(x))) XOR gamma(x).
```

The position comparisons above concern **right composition** alpha compose h,
where h is the input component of a self-equivalence of the **target T**.
Indeed, if T = b(T compose h)+c, substituting the first equation gives

```text
T = (b compose beta)(S compose alpha compose h) + b(gamma compose h) + c.
```

Thus alpha and alpha compose h occur in the same solution orbit. At position
x we may move a position in its orbit to x while retaining every earlier
position. This explains the comparisons alpha(x) <= alpha(h(x)).

A source self-equivalence instead acts by **left composition** h compose alpha,
and requires a correspondingly different filter under our function-composition
convention. The article uses left-action language and names the example
function t; here the explicit equations fix the convention for the reusable
code, independently of permutation-package multiplication conventions.
For Algorithm 3 source and target coincide, so either side is available.
For a general equivalence test the implementation explicitly uses target
self-equivalences. If only the source group is known, swap the two functions
for the decision search; a returned witness can be inverted.

## The recursive search

Alpha is an affine permutation and is left-refined at the least unknown
position. Affine closure can determine later entries immediately. Beta is an
invertible linear map: once alpha(x) is known, its relevant position is
S(alpha(x)), not necessarily the next integer. Gamma is affine and its value
at x is forced by T(x)+beta(S(alpha(x))). When gamma(x) is already known,
it forces the beta value instead. Every extension closes the corresponding
template under affinity. Conflicts reject the branch.

This is the three-template construction; gamma is not eliminated by affine
interpolation in this experiment. The Cython version writes newly determined
entries into shared arrays and passes domain and image masks by value.
An entry outside the current mask has no meaning and is not cleared on return.
It does not implement stopping, resumption, or parallel work scheduling.

The compiled default also propagates forced equations over **all** positions
already defined by alpha's affine closure. If beta(S(alpha(x))) is known,
gamma(x) is forced; if gamma(x) is known, the beta value is forced. Their
affine closures can force further values, so this repeats to a fixed point.
In particular S(alpha(x))=0 immediately forces gamma(x)=T(x), since beta(0)=0.
This is a documented scheduling optimization of the reconstruction, not a
claim about the missing original driver. It adds no generators or orbit rules.

Every assignment follows from an existing equality or affinity constraint,
so this propagation preserves every completion. Domain masks only grow during
closure, ensuring termination; a failed equality or injectivity test rules
out that branch. The basic readable search leaves this option off by default.
Both backends expose a `propagation` argument for comparison. The compiled
`propagation=False` path retains the simpler schedule. The finite checks
compare both schedules with their corresponding readable implementations;
the readable n=4 generator experiment supplies a further complete comparison.

The generator must be the least missing **alpha**, not merely the first
successful triple encountered by any interleaving of alpha and beta guesses.
This implementation retains the least successful alpha found so far and
prunes any input prefix that cannot improve it. This explicit incumbent bound
is an implementation choice of the reconstruction, not a recovered original
loop layout. It makes the ordering obligation reviewable despite the nested
beta search. Each returned triple is checked directly at all inputs.

## Why the pruning and generator loop are complete

Let K be the group generated so far. Let K_x fix positions 0,...,x-1
pointwise. For complete injective alpha, its least right-orbit condition is

```text
alpha(x) = min { alpha(y) : y in orbit(K_x, x) } for every x.
```

Necessity follows by composing with an element fixing all earlier positions
and bringing a smaller value to x. Conversely, suppose alpha compose h is
smaller, with first difference at x. Injectivity implies that h fixes each
earlier position, so h belongs to K_x and violates the displayed condition.
On a partial template, comparing two known values in such an orbit is a
sound rejection: that strict inequality persists in every completion.
When an orbit contains every remaining position and earlier values are
known, its minimum is the least unused output value. This yields the early
0 and 1 assignments in Note 9 without waiting to fill the whole orbit.

**Selected-generator lemma.** For a lexicographically greedy generator
sequence h_k = min(H minus H_k), the selected generators fixing a prefix
generate the whole prefix stabilizer in each intermediate H_k.

To see this, fix a prefix P. Before any generator moves P, all generated
elements fix P. Consider the first chosen generator h_j that moves P.
Every permutation fixing P is lexicographically smaller than h_j: at the
first moved position r of h_j, all smaller values have already been used,
so h_j(r)>r. By the choice of h_j, every element of H fixing P must therefore
already lie in H_j. All generators chosen before h_j fix P, so they generate
that entire stabilizer. Subsequent generators cannot enlarge it beyond H's
stabilizer. This also proves the statement for every intermediate group.

Consequently the article's selected-generator orbits suffice throughout the
greedy construction. This fact does **not** hold for arbitrary lists of
generators: their selected subsets can generate smaller stabilizers and give
weaker, though still sound, pruning. The verification compares the selected
orbits with full point-stabilizer orbits separately; the latter never feed
the historical search.

The identity is the least permutation. Its K-orbit is K itself, whose only
canonical member is the identity. Excluding the complete identity therefore
removes K, while each solution orbit outside K retains its least member.
The exact search returns min(H minus K), or exhausts the space if none exists.
Adding a returned generator strictly enlarges K; the finite process terminates.
The last exhausted search is essential: matching a published order is not a
stopping rule.

Lemma 7's hypotheses are checked for the inputs: the zero fiber contains the
standard affine basis, and the function's image spans the output space.
Then beta and gamma are unique for a given self-equivalence alpha, so |H|
is the full EA stabilizer order. The orbit size uses the same action-group
order as the [orbit calculation](ccz-stabilizers.md#orbit-sizes-and-coverage).
Under the product convention in article equation (7), projection onto alpha
reverses multiplication; taking inverses gives an isomorphism with the usual
permutation group. This does not change the subgroup or its order.

## Verification and original-source status

The finite suite compares all 65,536 ordered pairs of two-bit functions with
an independent ANF orbit criterion, compares 512 readable and compiled
searches, checks orbit pruning against explicitly enumerated group actions,
and enumerates affine inputs and linear outputs independently in dimension
three. For each supplied larger example it checks the generated group against
the independently computed modern group, and explicitly enumerates its
elements to check every canonical generator choice. No modern group element
is supplied to generator discovery.

The certificate replay rechecks transformation equations, the generated
subgroups and their orders, and the least-missing generator choices within
the final groups. It also checks the generic Note 9 filter against the literal
printed rules on 1,024 sampled affine prefixes with the first two images
fixed, ensuring the five-position rule is exercised. Replay does not repeat
the final negative searches; rerun the main experiment to repeat exhaustion.

Surviving private C variants retain the recursive input/output/correction
machinery and disabled hand-written orbit comparisons in `verify_a`. They
support this reconstruction's engineering provenance. The original complete
generator-search driver, its exact configurations, and the original set of
operators for every experiment have not been located. The maintained files
are a reconstruction from the paper, surviving related code, and the author's
clarifications, not recovered original source files.

For someone interested only in orders, the modern Sage group-intersection
experiment is a simpler route. For someone asking specifically to reproduce
Algorithm 3 and Note 9, the recursive code, the explicit three-stage filter,
and this provenance distinction are the relevant material.
